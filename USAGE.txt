DYFI Updater - Usage Guide

Overview
========
DYFI Updater keeps one or more dy.fi dynamic DNS hostnames in sync with your current external IP address.
It is made specifically for the dy.fi service at https://www.dy.fi/, which offers free dynamic DNS hostnames under the `.dy.fi` domain.

The dy.fi service lets Finnish users register up to five `.dy.fi` names and point them to a home computer, website, or other IP address.  
This makes it easy to run a home server on a dynamic IP and keep a stable hostname that follows the current address.  
If a dy.fi name is not currently pointed to an IP address, dy.fi can also forward browser requests to a configured homepage URL.  

The service is free and hobby-run, with minimal guarantees, and is intended for Finnish users.
It supports multiple implementation types in the repository:
- C#      (csharp/)
- Python  (python/)
- PowerShell (powershell/)
- Bash/Shell (shell/)
- Docker  (docker/)

Every implementation uses the same JSON-based configuration file format and the same update flow:
1. Ensure a local settings.json file exists in the same folder as the app.
2. Load settings from settings.json.
3. Detect the current external IP address using public IP services.
4. Update each configured dy.fi hostname if the IP changed, if UpdateNow is true, or if the force interval expired.
5. Save `lastupdate.txt` for schedule tracking and optionally log each run to `log.log`.

Usage
=====
Publication layout
------------------
The published package contains one folder for each implementation: csharp, python, powershell, shell, docker.
Each implementation folder contains its own `settings.json` and entrypoint script or executable.
The package root also contains the C# installer/uninstaller scripts described below.

General rules
-------------
- Run the executable or script from within its own implementation folder.
- Keep `settings.json` in the same folder as the app or executable.
- The app creates `lastupdate.txt` on first run and updates it after each successful update.
- If `UseLogFile` is enabled, the app writes `log.log` in the same folder.

Installing as a background service (C# build)
==============================================
The published package includes installer and uninstaller scripts that set up the C# executable
to run automatically in the background. These scripts operate only on the `csharp/` build; the
Python, PowerShell, Shell, and Docker implementations are run manually or scheduled by other means.

Linux - install.sh / uninstall.sh
----------------------------------
Requirements: run with sudo, from the root of the extracted release package.

Install:
  sudo ./install.sh

What it does:
- Detects your CPU architecture (x86_64 or aarch64) and selects the matching build.
- Copies the csharp/ folder (and any python/, docker/, powershell/, shell/ folders present) to
  /opt/dyfi-updater.
- Creates and enables a systemd service named `dyfi-updater` that starts on boot and restarts
  automatically if it stops.
- Runs the service as the user who invoked sudo (not as root).

Useful commands after installing:
  Status:  systemctl status dyfi-updater
  Logs:    journalctl -u dyfi-updater -f
  Stop:    sudo systemctl stop dyfi-updater
  Start:   sudo systemctl start dyfi-updater

Uninstall:
  sudo ./uninstall.sh

This stops and disables the systemd service, removes the service file, and deletes
/opt/dyfi-updater.

Windows - install.ps1 / uninstall.ps1
---------------------------------------
Requirements: run PowerShell as Administrator, from the root of the extracted release package.

Install:
  .\install.ps1
  .\install.ps1 -Method Startup

What it does:
- Detects your CPU architecture (win-x64 or win-arm64) and selects the matching build.
- Copies the csharp/ folder (and any python/, docker/, powershell/, shell/ folders present) to
  %ProgramFiles%\dyfi-updater.
- Registers the app to start automatically, using one of two methods:
  * TaskScheduler (default): creates a scheduled task that runs at logon and restarts
    automatically if it stops.
  * Startup: places a shortcut in your Startup folder instead, so the app launches whenever
    you log in.

Useful commands after installing with TaskScheduler:
  Status:  Get-ScheduledTask -TaskName dyfi-updater | Get-ScheduledTaskInfo
  Stop:    Stop-ScheduledTask -TaskName dyfi-updater
  Start:   Start-ScheduledTask -TaskName dyfi-updater

Uninstall:
  .\uninstall.ps1

This removes the scheduled task (if present), removes the Startup shortcut (if present), stops
any running instance, and deletes %ProgramFiles%\dyfi-updater. It cleans up whichever startup
method was used, so it works regardless of which -Method was chosen at install time.

Common settings.json schema
===========================
The configuration format is shared across all implementations.

Username
  Your dy.fi account username or email address.

Password
  Your dy.fi account password.

DomainNames
  Array of hostnames to update.
  Example:
  ["home", "office.dy.fi"]
  You do not need to include `.dy.fi` in the names; it is appended automatically if missing.

ForceUpdateIntervalDays
  Number of days before forcing a refresh even if the IP did not change.
  Default: 6
  Recommended: do not set lower than 3 days.

IpCheckIntervalMinutes
  How often the app checks the external IP address.
  Default: 2
  Minimum enforced value: 1 minute.

UpdateNow
  When true, performs an immediate update on the next loop iteration.
  The code resets this value to false after the update.

UseLogFile
  When true, the app appends log messages into `log.log`.
  When false, only console output is produced.

Example settings.json
=====================
{
  "Username": "my.email@email.com",
  "Password": "passw0rd",
  "DomainNames": ["address.dy.fi"],
  "ForceUpdateIntervalDays": 6,
  "IpCheckIntervalMinutes": 2,
  "UpdateNow": true,
  "UseLogFile": true
}

Implementation details
======================
C#
--
- The published C# build is a self-contained executable for each platform.
- Each runtime folder includes `settings.json` alongside the executable.
- The app reloads `settings.json` on every loop, so live edits are supported.
- `settings.json` is copied automatically into output folders during C# publish.
- Can be installed as a background service using install.sh (Linux) or install.ps1 (Windows);
  see "Installing as a background service" above.

Python
------
- Run `python dyfi_updater.py` inside the `python/` folder.
- Uses `requests` to fetch external IP and perform the dy.fi update.
- If `settings.json` is missing, it creates one from defaults.

PowerShell
----------
- Run `./dyfi_updater.ps1` inside the `powershell/` folder.
- Uses `Invoke-RestMethod` and a local `settings.json` file.
- If `settings.json` is missing, it creates one from defaults.

Shell
-----
- Run `./dyfi_updater.sh` inside the `shell/` folder.
- Uses `curl` and basic shell JSON parsing helpers.
- If `settings.json` is missing, it creates one from defaults.

Docker
------
- The Docker image runs the Python updater.
- The Dockerfile copies `python/dyfi_updater.py` and `python/settings.json` into `/app`.
- You can mount your own `settings.json` file into the container to override the example.
- Default command: `python dyfi_updater.py`.

Publish packaging
=================
When creating a published release using the repository's publish scripts, this `USAGE.txt` file is copied into the final package root.
That means the published archive contains the usage guide alongside the implementation folders.
The publish scripts also copy install.sh, install.ps1, uninstall.sh, and uninstall.ps1 into the
package root, and will fail the build if any of the four are missing from the repository.

Troubleshooting
===============
Cannot get external IP
----------------------
- Confirm the machine has internet access.
- Check that the public IP services are reachable.
- If one service fails, the implementations try multiple services in sequence.

Authentication failures
-----------------------
- Verify `Username` and `Password` in `settings.json`.
- Ensure your dy.fi account is active.

Domain update failures
----------------------
- Make sure each hostname in `DomainNames` is valid.
- If your entry lacks `.dy.fi`, the code appends it automatically.
- Check the service response in `log.log` if logging is enabled.

Scheduled updates
-----------------
- `lastupdate.txt` stores the last successful update timestamp.
- `ForceUpdateIntervalDays` controls how often the app updates even when the IP is unchanged.
- `UpdateNow: true` forces an immediate update on the next loop run.

Installer/uninstaller issues
-----------------------------
- Linux: install.sh and uninstall.sh must be run with sudo. If installation fails partway
  through, re-run uninstall.sh before trying install.sh again.
- Windows: install.ps1 and uninstall.ps1 must be run from an elevated (Administrator)
  PowerShell session. If installation fails partway through, re-run uninstall.ps1 before trying
  install.ps1 again.
- If a service or task from a previous version is still running, both installers stop and
  replace it automatically; you do not need to uninstall before upgrading.

Verifying builds
================
To verify that the executable files in this package are built from the source code in Program.cs:

1. Download the source code from the GitHub repository.
2. Build the C# project using the same publish scripts.
3. Compare the SHA256 hashes of the executables.

Each platform folder contains a `hashes.sha256` file with the expected hashes for the executables in that folder.
You can verify using:
- Windows: `certutil -hashfile dyfi-updater.exe SHA256`
- Linux/Mac: `sha256sum dyfi-updater`

The hashes ensure the .exe files are exactly as built from the provided source code.
